# BDR-001: デプロイコストを廃止しデプロイターン制を導入する

## ステータス

Accepted (2026-03-02)。旧 ADR-007 から移設。末尾の Amendment (2026-04: マイグレーションの廃止) を含めて現行仕様とする。

## 結論

デプロイ時に一括コスト（Budget）を支払うルールを廃止し、時間（ターン）ベースのメカニクスに置き換える。

- 全カードから `deploy_cost` を削除し、カードごとに `deploy_turns`（裏向き配置から稼働までのターン数）を持たせる。
- スターター選択（開始時のリソース 2 体選出）を廃止する。
- 開始直後の敗北を防ぐ稼働実績フラグと、立ち上げ遅延を敗北とする Launch Failure を導入する。
- Scale Up の Budget コストを廃止し、ランクに応じたメンテナンスコスト増だけにする。

デプロイにかかるのが費用でなく技術者の「時間」という現実のクラウド感覚にルールが一致し、「どの技術がデプロイに時間がかかるか」を体感させる教育目的も満たす。

## 背景・課題

現行ルールはデプロイ時に Budget（開発コスト）を一括で支払わせるが、現実のクラウドにデプロイ一括費用の概念はない。かかるのは技術者の「時間」であり、この違和感を解消したい。あわせて「どの技術がデプロイに時間がかかるか（＝設定が難しいか簡単か）」を体感させる教育目的がある。

## 詳細

### デプロイターン

- デプロイ時、カードは裏向きで配置され、`deploy_turns` 経過後に表向き（稼働中）になる。`deploy_turns = 0` は即時稼働。
- deploy_turns を持つのはリソースカード（Compute 系・Data 系）と Platform のみ。Attachment / Strategy / Incident / Reactive は従来どおり即時。
- card_type ごとのデフォルト値（即時=0 / VM・RDB=1 / Orchestrator・AI/ML・Platform=2）を持ち、カード単位で上書きできる。即時デプロイは Serverless のアイデンティティとする。

### 裏向きカードの扱い

稼働していない裏向きカードは、攻撃対象にならず、フィールド存在・System-Down 判定に数えず、メンテナンスコスト・Yield・パッシブ効果を持たない。ただしスロットは占有する。Frontend が裏向きのみなら Backend を直接攻撃できる。

### スターター廃止と開始フロー

開始時のリソース 2 体選出を廃止する（即時スターターは Serverless の即時デプロイの強みを打ち消すため）。開始は「デッキ 30 枚をシャッフル → 初期手札 5 枚 → T1 開始（フィールドは空）」とし、序盤戦略はデッキ構築で組む。

### 稼働実績フラグと Launch Failure

- スターター廃止で開始直後は全プレイヤーの表向きリソースが 0 枚になるため、一度でも表向きリソースを持ったプレイヤーにのみ System-Down 敗北を適用する（稼働実績フラグ）。
- 自分の 3 ターン目（先攻 T5 / 後攻 T6）のエンドフェーズ終了時に一度も稼働していなければ Launch Failure で敗北とする。

### Scale Up のコスト

Scale Up の Budget コストは廃止し、ランクに応じてメンテナンスコストが増加する（×1 / ×2 / ×3）。スケールアップに費用はかからないがランニングコストが増える実態に合わせる。

## Amendment: 2026-04 マイグレーション（リソース移行）の廃止

当初はデプロイターン制と同時にリソースのマイグレーション（SLA ペナルティなしで旧リソースを退役させる仕組み）を導入したが、サポート張り替え（占有スロットへのサポートカード配置）の導入に伴い廃止した。`migrate` アクション・イベントおよび関連フィールド（`migrating_from` 等）は削除済み。
