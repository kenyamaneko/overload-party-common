# BDR-003: サーバの停止で切れた対戦を無効とする

## ステータス

Proposed (2026-07-26)

## 結論

gateway の停止によって接続が切れた対戦は無効とし、勝敗をつけず、消費したバトル回数を両プレイヤーに戻す。

- 停止の時点で決着していない対戦が対象になる
- 勝敗を記録せず、経験値も付与しない
- マッチメイキングの開始時に消費したバトル回数を戻す
- 片方が既に切れていた対戦も、停止に巻き込まれた時点で無効とする

[BDR-002](002-disconnect-resolution.md) が定めた 120 秒の猶予は、プレイヤー側の事情で切れた場合に適用する。本 BDR は停止によって切れた場合を切り分ける。

## 背景・課題

BDR-002 は切断の原因を区別せず、猶予を過ぎたプレイヤーを負けとしている。この規則のもとでは、こちらがサーバを止めたことによる切断も、プレイヤー自身の切断と同じ扱いになる。

gateway は最大 1 インスタンスで動くため ([ADR-058](../adr/058-gateway-on-cloudrun-single-instance.md))、新しいリビジョンへの入れ替えで進行中の対戦がすべて同時に切れる。復帰が猶予に間に合わなければ、プレイヤーは自分の操作と無関係に負ける。運営の都合で敗北を与えることになり、対戦の結果として受け入れられない。

バトル回数についても同じことが言える。回数はマッチメイキングの開始時に消費される。停止で対戦が成立しなかった場合、プレイヤーは遊べていないのに 1 回ぶんを失う。

一方で、切断を繰り返して回数制限を回避する抜け道を作ってはならない。プレイヤーが自分で切断した場合に回数を戻すと、対戦を始めては切ることで制限を無視できる。

原因によって扱いを分けることで両立する。サーバの停止はプレイヤーには起こせないため、無効試合を意図的に発生させる経路が無い。

## 詳細

- 対象は停止の時点で決着していない対戦に限る。既に勝敗が確定した対戦は通常どおり記録する
- 無効になった対戦は勝者なしの引き分けとは異なる。引き分けは対戦の結果だが、無効は対戦が成立しなかったことを表す
- 戻す対象は、その対戦のために消費したバトル回数である。両プレイヤーが対象になる
- プレイヤー側の事情で切れた対戦の扱いは BDR-002 のままとする。回数は戻さない
