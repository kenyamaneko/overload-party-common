# Overload Party — ドメイン用語集（GLOSSARY）

ゲームのドメイン概念を指す語と、コード上の表記を対応づける変換表。

## このファイルの使い方（ルール）

- **ゲームのドメイン概念を指す語は、この表にあるものだけを使う。**
- 表にない語でドメインを表現しない。コメント・識別子・doc いずれも対象。
- 新しいドメイン概念が必要になったら、**勝手に命名せず、まずこの表に追記する**。追記の提案だけ行い、表が更新されてから使う。
- 一般プログラミング語彙（`cache` / `registry` / `handler` / `processor` / `context` 等、ゲームのルール上の概念ではない語）はこの表の対象外。判断基準は「これは RULEBOOK に出てくるゲームのルール上の概念か？」。

## 表の読み方

- **ドメイン概念**: RULEBOOK 上の正式な日本語名。
- **コード識別子**: C# / YAML 等で使う英語表記。
- **コメント表記**: コード内コメント・doc で使う日本語表記。
- **備考**: 定義、混同しやすい語、概念の包含関係。

## ゾーン・盤面

| フロントエンド | `Frontend` | フロントエンド | コンピュート系リソース等を置く 3 枠。攻撃の壁 |

## 効果・トリガー

| ドメイン概念 | コード識別子 | コメント表記 | 備考 |
|---|---|---|---|
| 効果 | `Effect` | 効果 | カードが持つ効果全般 |
| 誘発効果 | `TriggeredEffect` | 誘発効果 | リソース等が特定イベントで自動発動する効果。**リアクティブ（カードタイプ）とは別概念**。誘発効果はカードが持つ「効果」、リアクティブは独立した「カードタイプ」 |
| 発動条件 | （カードごと） | 発動条件 | 効果が発動するための条件。「ガード」はコード内部の判定機構の語であってドメイン語ではない |
| パッシブ効果 | `PassiveEffect` | パッシブ効果 | 常時適用される継続効果 |
| デプロイ時効果 | `OnDeploy` | デプロイ時効果 | デプロイ完了時に発動する誘発効果 |
| 起動効果 | `Ignition` | 起動効果 | プレイヤーが手動で起動するアクティブ効果 |
| エンドフェーズ効果 | `OnEndPhase` | エンドフェーズ効果 | エンドフェーズに発動する効果 |
| イベント | `Event` | イベント | 攻撃宣言・デプロイ・破壊・被ダメージ等、効果の発動契機 |
| DeployOrder | `DeployOrder` | デプロイ順 | カードがフィールドに出た順序。同時発動の解決順に使う |

> リアクティブが応じる「特定のイベント」は、攻撃宣言時 / リソースのデプロイ時 / リソースの破壊時 / インシデント使用時 / リソースの被ダメージ時 など。これらはリソースの誘発効果の契機でもある。**イベントは誘発効果とリアクティブの両方の契機になりうる**ため、`on_*` トリガーをリアクティブ専用の語として扱わない。

## メンテナンス

- 概念の包含関係に変更が生じたら備考列を必ず更新する（例: サポートカード ⊃ リアクティブ）。
- RULEBOOK が更新されたら、この表との差分を確認する。
- 「コード識別子」列が空欄の概念は、まだコード化されていないか命名が未確定。コード化時にこの表で命名を確定させる。

## ローカル hook 連携

`overload-party-battle/` または `overload-party-battle.wt/` 配下を Edit / Write する際、Claude Code が本ファイルと RULEBOOK の参照を強制されるよう、common の `.claude/settings.json` に PreToolUse hook を仕込むことを想定している（`.claude/scripts/battle-glossary-reminder.txt` がリマインダー本文）。

`.claude/settings.json` は `.gitignore` 対象なので hook 設定はローカル管理。チームで揃えたい場合は各自で同等の hook を設定する。
