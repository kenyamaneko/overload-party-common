# ADR-070: デイリーバトル回数を履歴台帳として持ち、TOCTOU を許容する

## ステータス

Accepted

## 結論

account が持つプレイヤーごとのデイリーバトル回数は、プレイヤーとゲーム日の組で 1 行を持つ履歴台帳として管理する。プレイヤー登録時には行を作らず、当日はじめてのバトルで初めて行が発生する。上限判定はトランザクションで厳密に直列化せず、TOCTOU (判定から加算までの間に競合が起きうる隙間) を許容する。

## 背景・課題

デイリーバトル回数は「当日何回戦えるか」という上限判定に使うだけでなく、プレイヤーごとの日次推移を残す唯一の場所でもある。登録時に当日分の行を作ると、登録日とバトルを始めた日の紐付けが不要な依存として生まれる。

上限判定は「現在の回数を読む」→「上限未満なら加算する」という 2 手順に分かれる。これを 1 トランザクションに厳密に囲えば同時実行時の取りこぼしを防げるが、同一アカウントで上限ぎりぎりの対戦を並行して行うのは極めて稀なエッジケースであり、行ロックや同一トランザクション化のコストに見合わない。

## 不採用案

### 判定と加算を 1 トランザクションで囲み、行ロックで直列化する

却下。同一アカウントの並行バトルという稀にしか起きない競合を防ぐために、通常経路すべてに行ロックのコストを持たせることになる。加算自体は単発の更新で原子的に行えるため、回数が壊れる (飛ぶ・重複する) ことはなく、許容する競合は「ぎりぎり1回多く通る可能性」に限られる。

### 登録時にゲーム日の行を作っておく

却下。登録とバトル履歴のライフサイクルが本来独立しているのに、初期化の都合で結合してしまう。当日の行が無ければ回数 0 とみなす扱いで十分読み出せる。
