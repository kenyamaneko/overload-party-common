# ADR-074: 対戦運用処理を battle でなく gateway に置く

## ステータス

Accepted (2026-08-11)

## 結論

battle を対戦ロジックのみを持つ受動的なエンジンに保つため、対戦の進行に関わる運用処理は gateway 側に置く。対象は、マッチ成立の検知、手番と接続断の実時間計測、NPC 対戦の連続進行、演出用イベントの組み立ての 4 種類である。battle はこれらに必要な実時間・購読・セッションの概念を持たない。

## 背景・課題

battle は 1 リクエストにつき 1 手を進めるだけの REST エンジンとして意図的に設計されており、実時間の経過・イベントの購読・プレイヤーの接続状態を扱わない。一方で対戦の進行には、マッチが成立した通知を受け取って対局を開始する、手番や接続断の制限時間を実時間で計測して敗北を確定させる、NPC の手番を人間の操作を待たずに連続して進める、対局開始時の演出用にサーバー側のイベント順とは別の合成イベントを組み立てる、といった処理が要る。これらはいずれも実時間の経過やクライアントとの接続状態に依存し、対戦ロジックそのものではない。

WS 接続を保持し外部からの通知を受け取れるのは gateway だけであるため、これらの処理は必然的に gateway 側に集約される。

## 不採用案

### 対戦の運用処理を battle 側に寄せる

実時間の計測・外部通知の購読・接続状態の追跡を battle に持たせる案。対戦ロジックに専念させることで得ていた見通しの良さ ([ADR-002](002-battle-server-csharp-separation.md)) を失うため採用しない。
