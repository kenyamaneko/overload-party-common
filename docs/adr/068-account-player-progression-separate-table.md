# ADR-068: account の level / exp を players から物理分離する

## ステータス

Accepted

## 結論

プレイヤーのレベル・経験値を `players` に同居させず、1:1 の子テーブルに切り出す。プロフィール系の低頻度更新と、戦闘ごとに発生する高頻度更新のライフサイクルを物理的に分離することで、更新頻度の異なるデータが同じ行ロック・同じ VACUUM 対象を奪い合う状態を避ける。

## 背景・課題

レベル・経験値は戦闘終了のたびに更新されるのに対し、プレイヤー名やプレミアム状態などのプロフィール情報は低頻度にしか変わらない。両者を同じ行に同居させていた実装では以下の問題が生じていた。

- プロフィール系の `updated_at` が戦闘の頻度で動いてしまい、「プロフィールが変更されたかどうか」の検知に使えなくなる
- 経験値加算の行ロックがプロフィール行全体を巻き込み、プロフィール更新と競合する
- 高頻度 UPDATE の dead tuple がプロフィール系のテーブルに集中し、VACUUM コストが上がる

読み出し側の API 契約 (レスポンスに level / exp を含む) は変えたくないため、分離後も呼び出し元からは 1 つの集約として見える形にする必要がある。

## 不採用案

### 同一テーブルのまま運用する

却下。上記 3 つの問題が解消されないままになる。
