# ADR-079: matchmaking キューは Redis 障害時にフォールバックを持たず即座に失敗させる

## ステータス

Accepted (2026-08-11)

## 結論

Upstash Redis に到達できない場合、matchmaking はインメモリなど代替のキューにフォールバックせず、enqueue / cancel / pop を即座に失敗させ 503 を返す。

## 背景・課題

matchmaking は複数インスタンスに水平スケールし、待機キューは Upstash Redis の Sorted Set に一元化されている ([ADR-010](010-matchmaking-queue-upstash-redis.md), [ADR-012](012-matchmaking-pubsub.md))。Redis 障害時にインメモリキューへ切り替える案には次の問題がある。

- 各インスタンスがそれぞれ別のインメモリキューを持つことになり、プレイヤーがインスタンスごとに分断されたキューに散らばってペアリングが成立しなくなる
- Redis 障害中に受け付けたプレイヤーを、Redis 復旧後に正規のキューへ合流させる経路が無く、他インスタンスから見えないキューに取り残されたままになる

## 不採用案

### Redis 障害時にインメモリキューへフォールバックする

却下。上記 2 点の通り、複数インスタンス間でキューが分断される問題と、復旧後にインメモリ側のプレイヤーを正規キューへ合流させる手段が無い問題を解消できない。
