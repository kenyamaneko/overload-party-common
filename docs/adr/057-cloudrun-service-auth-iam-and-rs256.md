# ADR-057: Cloud Run 移行に伴うサービス間認証の再設計

## ステータス

Accepted (2026-07-24)

この ADR は [ADR-037](037-internal-auth-hmac-signed-jwt.md) を置き換える。内部認証トークンの署名を対称鍵 (HS256) から非対称鍵 (RS256) へ変更し、サービス間の到達制御と利用者 identity の伝播を別々の仕組みに分離する。[ADR-056](056-retire-gke-gitops-return-to-cloudrun.md) の Cloud Run 移行に伴い、GKE の網境界が失われることへの対応である。

## 結論

Cloud Run 上のサービス間認証を次の二層で構成する。

- **到達制御**: 各サービスを Cloud Run の呼び出し IAM で保護し、呼び出し元のサービス identity で認可する。battle を含む全サービスに適用する
- **利用者 identity の伝播**: gateway が外部トークン (Firebase) を端で検証してプレイヤー identity を解決し、非対称鍵 (RS256) で署名した内部トークンに載せて下流へ伝播する。下流は gateway の公開鍵で検証する

プレイヤーのデータを操作するサービスは、内部トークンからプレイヤー identity を受け取る。battle は純粋なバトルロジックに徹してプレイヤー identity を持たず、到達制御の IAM のみを受ける。プレイヤーの外部 identity (Firebase UID) と内部 identity (プレイヤー ID) は別物として保ち、変換は gateway で一度だけ行う。

## 背景・課題

GKE 構成では、サービスはクラスタ内 IP のみを持ちインターネットから到達不能で、この private network がサービス間の到達制御を実質的に担っていた。内部認証の共有 HS256 トークンは主に利用者 identity の伝播を担い、到達制御は網が支えていた。

Cloud Run では各サービスが既定で公開エンドポイントを持つため、この暗黙の網境界が失われる。共有対称鍵は検証者が署名者を兼ねられるため、鍵を持つ者は誰でもトークンを偽造でき、公開網ではこれ単独を境界にできない。実際、battle はアプリ層の認証を持たず網の到達不能性のみに依拠しており、公開されれば無認証で盤面操作を受ける。

到達制御と identity 伝播という異なる二つの問いが一つの共有鍵に混在していた。移行を機にこれを分離し、到達制御は基盤 (Cloud Run の呼び出し IAM) に委ね、identity 伝播の内部トークンは非対称化して、下流が検証はできるが偽造はできない状態にする。

## 不採用案

### 各サービスが Firebase トークンを直接検証する

利用者 identity を各サービスが真実の源から検証する案。しかしプレイヤー ID は Firebase UID とは別物で account サービスが解決するため、各サービスが解決を重複させ account へ結合する。さらに gateway のタイマーのように利用者リクエストが存在しない契機ではトークンが無く、この経路を扱えない。生の外部トークンを全サービスへ配ることにもなり漏洩面が広がるため採用しない。

### private network を再建してサービスを非公開にする

Cloud Run を VPC 内からのみ到達可能にし、GKE の網境界を再現する案。到達制御を IAM に委ねれば公開エンドポイントのままでも未認証を弾けるため、網境界の再建は不要と判断した。

### 共有 HS256 を継続する

実装変更は最小で済むが、公開網では鍵を持つ者が任意プレイヤーへのなりすましトークンを作れる。鍵漏洩時の被害が全プレイヤーに及ぶため非対称化する。

### Firebase UID をプレイヤー ID にする

account の identity 解決を省ける利点があるが、認証プロバイダの識別子がドメインの主キーとなり、全サービス・全外部キー参照・イベント・ログへ広がる。プロバイダ移行時に identity キーを全面的に書き換えることになり、プロバイダ非依存の継ぎ目を失うため採用しない。
