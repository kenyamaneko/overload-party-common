# ADR-073: Pub/Sub 発行を Transactional Outbox で DB commit と同一トランザクションに揃える

## ステータス

Accepted (2026-08-11)

## 結論

DB へのビジネス上の書き込みと Pub/Sub への発行を、同一トランザクションでの outbox 行書き込みを介して結合する (Transactional Outbox パターン)。発行は常駐 worker が outbox 行を定期的に claim して行う。claim は行ロックを publish 完了まで保持せず、claim 時刻を記録して一定時間だけ他 worker から見えなくする方式にする。この結果、配信は少なくとも 1 回 (at-least-once) の保証にとどまり、受信側の冪等性で重複を吸収する前提を置く。

shop が最初に採用し、同型の仕組みを scenario も採用している。

## 背景・課題

DB へのコミットと Pub/Sub への発行を別々の操作として行うと、片方だけが成功して整合が崩れる (dual-write 問題)。発行だけを外部に切り出さず、ビジネス上の書き込みと同じトランザクションで完結させる必要がある。

一方、発行自体は非同期な worker に任せるため、複数 pod が同時に稼働する環境で同じ行を重複して処理しない仕組みが要る。行ロックを publish が終わるまで保持する案は、publish 中に worker がクラッシュするとロックが長時間残り、他の worker がその行を拾えなくなる。

## 不採用案

### claim した行のロックを publish 完了まで保持する

複数 worker の重複処理は防げるが、publish 中に worker がクラッシュするとロックが解放されず、当該行がどの worker からも拾われないまま滞留する。claim 時刻を記録して一定時間で自動的に他 worker へ解放する方式の方が、運用操作なしでクラッシュから回復できるため、こちらは採用しない。
