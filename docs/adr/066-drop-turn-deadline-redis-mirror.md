# ADR-066: ターン期限の Redis 写しをやめる

## ステータス

Accepted (2026-08-06)

[ADR-059](059-gateway-timer-state-in-memory-with-redis-backup.md) の一部を撤回する。

## 結論

gateway が保持するターン期限の Redis (Upstash) への写しをやめ、インメモリのみで持つ。切断猶予期限の写しは維持する。使われていない読み出し経路が無くなり、書き込みも不要になる分コードが単純になる。

## 背景・課題

ADR-059 は切断猶予期限とターン期限の両方を対象に Redis への写しを導入したが、ターン期限側は書き込みだけが行われ、プロセス再起動をまたいだ復元を読み出す実装はどこにも存在しなかった。

ターンタイマーは、切断猶予期限とは異なる形で既に復元相当の動作が成立している。WS が再接続すると、クライアントは必ずゲーム参加状態を送り直す。gateway はこれを受けて battle server から最新の持ち時間を取得し、ターンタイマーを組み直す。gateway が再起動すればその影響を受けたプレイヤーの WS 接続は必ず切れ、再接続時にこの経路を通るため、写しが無くてもターンタイマーは自己修復する。この経路は battle server の権威ある状態を使うため、写しを書き込んだ後に行われたアクションも反映でき、絶対時刻の写しを読み戻すより正確でもある。

切断猶予期限には対応する自己修復経路が無い。接続そのものを保持するのはプロセスであり外に置けず、盤面と手番は battle が持つが、「どちらがいつ切断したか」を知っているのは gateway だけである。この非対称性から、ターン期限の写しだけを取りやめる。

## 不採用案

### 書き込みは残し、読み出しだけ実装する

ターン期限の復元を実装する案も検討したが、上記の理由により自己修復が既に成立しており、写しを読み戻す経路を追加しても得られる正確性はむしろ下がる (書き込み後のアクションを反映できない) ため採用しない。
