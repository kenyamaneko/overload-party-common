## 1. 設計方針

### 基本方針

- **ガチャなし**: 確率に依存した課金要素は一切設けない
- **Pay-to-Win なし**: 課金によるゲーム内有利（強いカード限定販売等）はなし
- **透明性**: 何を買えば何が手に入るかを明確にする
- **無課金でも楽しめる**: 1日10回のバトルが可能。初期デッキで対戦参加できる

### 課金の目的

| 目的 | 手段 | 決済種別 |
|------|------|---------|
| バトル回数制限の解除 | プレミアムプラン | サブスクリプション（月額） |
| カードコレクション拡張 | 陣営カードセット購入 | 買い切り |
| コレクション要素 | イラスト違いカード、プレイマット、スリーブ等 | 買い切り |
| スタンプ（エモート）拡張 | 陣営スタンプセット購入 | 買い切り |

## 2. プランと制限

### プラン比較

| 機能 | 無課金 | プレミアム（サブスク） |
|------|--------|----------------------|
| バトル回数 | 10回/日 | **無制限** |
| カード入手 | 初期選択の1陣営 + Neutral | 同左（追加陣営は別途購入） |
| コレクション | なし | なし（別途購入） |
| デッキ保存数 | 最大10デッキ | 最大10デッキ（同じ） |
| ランキング参加 | 可能 | 可能 |

> **注意**: プレミアムプランはバトル回数制限の解除のみ。カード入手やコレクションは別途買い切り購入。

### 課金種別

```
課金種別
├── プレミアムプラン（バトル無制限）
│   └── サブスクリプション（月額）
├── 陣営カードセット購入
│   └── 買い切り（残り陣営の解放）
└── コレクション
    ├── イラスト違いカード（買い切り）
    ├── プレイマット（買い切り）
    ├── スリーブ（買い切り）
    └── 陣営スタンプセット（買い切り）
```

## 3. バトル制限システム

### 仕様

| パラメータ | 値 |
|-----------|-----|
| 無課金バトル上限 | 10回/日 |
| プレミアムバトル上限 | 無制限 |
| リセット時刻 | JST 5:00（UTC 20:00） |
| NPC戦 | 回数にカウント |
| PvP戦 | 回数にカウント |

### 動作フロー

```
バトル開始リクエスト（PvP / NPC）
        │
        ▼
  プレミアム会員？
   ┌────┴────┐
  Yes       No
   │         │
   │         ▼
   │   本日のバトル回数 < 10？
   │    ┌────┴────┐
   │   Yes       No
   │    │         │
   │    ▼         ▼
   │  回数+1      エラー返却
   │    │       「本日のバトル上限」
   │    │
   └────┤
        ▼
    バトル開始
```

### リセット仕様

- ゲーム日はJST 5:00（UTC 20:00）を境界として判定
- `PlayerDailyBattle.last_reset_date` がゲーム日と異なる場合、カウントを0にリセット
- リセットはバトル開始時に遅延実行（バッチ処理不要）

### NPC対戦

PvPに加え、NPC（AI）との対戦が可能。

| パラメータ | 値 |
|-----------|-----|
| ゲームエンジン | PvPと同一 |
| AI方式 | ルールベース（コスト効率・フィールド状況判断） |
| NPCデッキ | 陣営ごとの固定デッキ |
| デイリーカウント | PvPと合算でカウント |

**NPC対戦API（REST）:**

| メソッド | エンドポイント | 説明 |
|---------|--------------|------|
| POST | `/api/v1/npc/battle/start` | NPC対戦を開始 |
| POST | `/api/v1/npc/battle/:gameId/select` | 開始リソースを選択 |
| POST | `/api/v1/npc/battle/:gameId/action` | アクションを実行 |
| GET | `/api/v1/npc/battle/:gameId/state` | ゲーム状態を取得 |

> NPC対戦はWebSocketを使用せず、RESTで完結する。NPCのアクションはプレイヤーのリクエスト内で同期的に実行される。

## 4. カード入手モデル

### カード解放の流れ

```
1. ユーザー登録後、初回ログイン時
   └── プレイヤーが陣営を1つ選択 → その陣営 + Neutral の全カードを解放

2. ショップで課金（買い切り）
   └── 残りの陣営のカードを個別に購入・解放
```

| 段階 | 解放される陣営 | 条件 |
|------|--------------|------|
| 初期選択 | プレイヤーが選んだ1陣営 + Neutral | 初回ログイン後に陣営選択 API を呼ぶ |
| 課金（買い切り） | 残りの陣営（個別購入） | ショップで陣営カードセットを購入 |

> **無課金でも1陣営 + Neutral のカードが揃う**ため、対戦に参加できる設計。Neutral カードは全プレイヤーが最初から使用可能。

### 陣営カードセット購入（課金）

| セット名 | 内容 | 決済種別 |
|---------|------|---------|
| SHEセット | SHE陣営の全カード | 買い切り |
| 天気使いセット | 天気使い陣営の全カード | 買い切り |
| しゅがーらぼセット | しゅがーらぼ陣営の全カード | 買い切り |
| 調律部セット | 調律部陣営の全カード | 買い切り |

> 既に解放済みの陣営セットは購入不可（または購入済み表示）。

## 5. コレクション

ゲームバランスに影響しない装飾要素。すべて買い切り。
DB管理: `CosmeticItems`（定義）+ `PlayerItems`（所持）テーブル（`item_type` で種別を区別）。

### イラスト違いカード

同一カードの別イラスト版。効果・能力は通常版と完全に同一。

**管理方法:**

```
PlayerCards テーブル
├── card_no: 1 (えくぼ 通常版)
│   └── illustration_variant: 0
└── card_no: 1 (えくぼ 別イラスト版)
    └── illustration_variant: 1
```

- デッキ構築時にどちらのイラストを使うか選択可能

### プレイマット

対戦画面のフィールド背景デザイン。

- `item_type = "playmat"`
- デッキ設定画面で選択・装備。`Decks.playmat_no` に保存

### スリーブ

カード裏面のデザイン。

- `item_type = "sleeve"`
- デッキ設定画面で選択・装備。`Decks.sleeve_no` に保存

### アイコン

プロフィールアイコン（アバター画像）。

- `item_type = "icon"`
- プロフィール設定画面で選択。`Players.equipped_icon_no` に保存

## 6. スタンプシステム

対戦中にプレイヤー同士が送り合う非言語コミュニケーション機能（エモート）。
ゲームバランスに一切影響しないコスメティック要素。

- `item_type = "stamp"` で管理

### 無料スタンプ一覧（初期配布・全プレイヤー共通）

| No. | スタンプ名 | 使いどころ |
|-----|-----------|-----------|
| 1 | よろしくお願いします！ | 対戦開始の挨拶 |
| 2 | ヨシ！ | 完璧な盤面を作った時、確認 |
| 3 | 仕様です | 痛いところを突かれた時の言い訳、カウンター時 |
| 4 | LGTM | 相手の良いプレイへの称賛 |
| 5 | 進捗ダメです | 劣勢時・リソース枯渇時のSOS |
| 6 | 完全に理解した | とりあえず強いカードを出した時（実は分かってない） |
| 7 | 何もわからない | パニック時・相手の長考や複雑なコンボを見た時 |

### 課金スタンプセット（陣営別）

| セット名 | 内容 | 価格 |
|---------|------|------|
| SHEスタンプセット | SHE陣営キャラクタースタンプ | 480円 |
| 天気使いスタンプセット | 天気使い陣営キャラクタースタンプ | 480円 |
| しゅがーらぼスタンプセット | しゅがーらぼ陣営キャラクタースタンプ | 480円 |
| 調律部スタンプセット | 調律部陣営キャラクタースタンプ | 480円 |

> 課金スタンプのキャラクターデザインはリリースに向けて順次追加予定（現在 is_active = false）。

### 実装仕様

- **付与**: プレイヤー登録時に無料スタンプ No.1〜7 を `PlayerItems` に自動 INSERT
- **送信**: WS `use_stamp` → サーバーが同ゲームの相手に `stamp_used` をブロードキャスト
- **所持確認**: MVP ではサーバーサイド検証なし（コスメティックのみのため不正の実害なし）

## 7. デッキ管理

### デッキ仕様

| パラメータ | 値 |
|-----------|-----|
| 最大デッキ数 | 10 |
| デッキ枚数 | 30枚固定 |
| 課金による上限変更 | なし |

### デッキ有効性チェック

デッキ保存時に以下を検証する:

1. **枚数**: ちょうど30枚
2. **所持確認**: 全カードがPlayerCardsに存在する
3. **陣営制限**: ルールブックに従った構成（Neutral以外は1陣営のみ等）

```
デッキ保存
    │
    ▼
枚数 = 30枚？ → No → エラー「30枚必要です」
    │ Yes
    ▼
全カード所持済み？ → No → エラー「未所持カードが含まれています」
    │ Yes
    ▼
陣営ルール適合？ → No → エラー「陣営ルール違反」
    │ Yes
    ▼
is_valid = true で保存
```

## 8. 課金フロー

### プレミアムプラン（サブスクリプション）

```
ユーザー操作                  アプリ                   Apple / Google
     │                          │                          │
     │  1. プレミアム登録ボタン  │                          │
     ├─────────────────────────>│                          │
     │                          │  2. サブスク開始リクエスト │
     │                          ├─────────────────────────>│
     │                          │<─────────────────────────┤
     │  3. 決済UI表示            │                          │
     │  4. 決済操作              │                          │
     │                          │  5. サーバー通知           │
     │                          │  (App Store Server Notif / │
     │                          │   RTDN)                   │
     │                          │  6. is_premium = true     │
     │                          │     premium_expires_at 更新│
     │                          │     (PostgreSQL更新)       │
     │  7. プレミアム有効化完了  │                          │
     │<─────────────────────────┤                          │
```

**サブスク更新・解約:**

| イベント | 処理 |
|---------|------|
| 自動更新成功 | Apple/Google からのサーバー通知で `premium_expires_at` を次の期限に延長 |
| 解約（期間終了） | `premium_expires_at` を過ぎたらデイリー制限（10回/日）に戻す |
| 解約（即時ではない） | 解約申請後も `premium_expires_at` までは有効 |
| 更新失敗（猶予期間） | Apple/Google の猶予期間中はプレミアム維持。猶予終了後に失効 |

### カードセット・コレクション購入（買い切り）

```
ユーザー操作                  アプリ                    PostgreSQL
     │                          │                          │
     │  1. 商品選択・購入        │                          │
     ├─────────────────────────>│                          │
     │                          │  2. 決済処理              │
     │                          │  (App Store / Google Play) │
     │                          │                          │
     │                          │  3. 購入完了後            │
     │                          │     - 陣営セット → PlayerCards│
     │                          │       に対象カード一括INSERT│
     │                          │     - コレクション → 所持  │
     │                          │       テーブルに INSERT    │
     │                          ├─────────────────────────>│
     │                          │<─────────────────────────┤
     │  4. 購入完了              │                          │
     │<─────────────────────────┤                          │
```

### 決済基盤

| プラットフォーム | 決済手段 | サーバー通知 |
|----------------|---------|-------------|
| iOS | App Store In-App Purchase | App Store Server Notifications V2 |
| Android | Google Play Billing | Real-time Developer Notifications (RTDN) |

- レシート検証はサーバーサイドで実施（クライアント検証は不可）
- 購入完了後、PostgreSQLへの反映は冪等に実装（重複購入を防ぐ）
- サブスクの状態変更（更新・解約・猶予期間等）はサーバー通知で受信

## 10. 実装上の注意点

### バトル回数制限

- バトル回数はバトル**開始時**に消費（終了時ではない）
- 接続切断・相手の降参等でバトルが中断した場合もバトル回数は返還しない
- バトル回数の計算はサーバーサイドのみで行う（クライアントの値は信頼しない）

### 課金状態の確認

- `is_premium` はバトル開始時・マッチング時に確認
- `premium_expires_at` で期限切れを確認（サブスク更新が正常ならサーバー通知で自動延長される）
- 期限切れの場合はデイリー制限（10回/日）に戻す

### 不正対策

- バトル回数はサーバーで管理し、クライアントからの改ざんを防ぐ
- カード所持確認はデッキ使用時にサーバーで再検証
- 決済レシートはApple/Google APIで検証後にDBを更新
