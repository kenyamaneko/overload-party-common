### リポジトリ切れに関する問題

**18%がリポジトリ切れ**は比較的高い数値です。

#### 可能性のある原因

1. **過剰なドロー/サーチ**: Strategy cardsでリポジトリを使い切る
2. **長期戦**: 11+ターンのゲームが22%
3. **Budget管理の失敗**: Budgetを温存しすぎて、リポジトリだけが消費される

#### 調査が必要な点

- ❓ リポジトリ切れで終わったゲームの平均Budget
- ❓ リポジトリ切れで終わったゲームの平均ターン数
- ❓ どの陣営がリポジトリ切れになりやすいか

## 🔍 #27/#32コンボに関する調査結果

### 現状の問題

**AozoraAIは#27と#32のコンボを優先していない**

#### 理由

1. **FactionAIの実装**:
   - パラメータ調整のみ（budget floor, attack floor, instance family等）
   - カード個別の優先度ロジックがない

2. **AozoraAIの設定**:
   ```go
   deployFloor: 2000  // 保守的（Budget温存）
   cheapDeployFirst: false  // 高コストカードを優先
   instanceFamily: "R"  // Regular (高可用性重視)
   ```

3. **カード選択ロジック**:
   - コストベースのソート（高→低 or 低→高）のみ
   - カードシナジーを考慮しない

### 推奨改善策

#### 1. カード優先度システムの実装

```go
type CardPriority struct {
    cardNo   int64
    priority int  // 高いほど優先
}

// Aozora特有の優先度
func (ai *AozoraAI) getCardPriority(cardNo int64, field *model.Field) int {
    switch cardNo {
    case 32:  // CosmosDB - 最優先（#27とのコンボ用）
        return 100
    case 27:  // Azure OpenAI - #32がいれば高優先度
        if hasCardOnField(field, 32) {
            return 90
        }
        return 70
    case 30:  // SQL Supercell - Failover synergy
        if countAozoraDBOnField(field) >= 2 {
            return 85
        }
        return 60
    default:
        return 50  // デフォルト
    }
}
```

#### 2. デプロイ順序の最適化

**現在**: コストのみでソート
**推奨**: 優先度 → コスト の順でソート

```go
// 1. #32 (CosmosDB) を先にデプロイ
// 2. #27 (Azure OpenAI) を次にデプロイ
// 3. 他のAozora DBカードで#27を強化
```

## 💡 改善提案

### 1. Aozoraバランス調整（緊急）

#### 問題
- 勝率30%は許容範囲外
- どのAIでも勝てない → デッキの問題

#### 提案

**A. カード#27の強化**:
- 現在: バックエンドのAozora DB + ObjectStorageごとにTP +200
- 提案: ボーナスを +250 または +300 に増加

**B. 新しいAozoraカードの追加**:
- 低コストの強力なコンピュート系リソース
- 序盤のテンポを改善

**C. 既存カードの調整**:
- カード#30 (SQL Supercell) の効果を強化
- カード#24 (Aozora PaaS) のコストを削減

### 2. AozoraAIの改善（重要）

#### A. #27/#32コンボの実装

```go
func (ai *AozoraAI) shouldDeployCosmoDB(field *model.Field, hand []model.HandCard) bool {
    // #32がデッキにあり、手札に#27がある場合は優先的にデプロイ
    hasAzureAI := hasCardInHand(hand, 27)
    hasCosmoDB := hasCardInHand(hand, 32)
    return hasCosmoDB && (hasAzureAI || !hasCardOnBackend(field, 32))
}
```

#### B. Budget管理の改善

```go
// AozoraAIのdeployFloorを調整
deployFloor: 1500  // 2000 → 1500 (より積極的に)
```

### 3. リポジトリ切れ問題の調査（中優先度）

#### 必要な調査

1. **リポジトリ切れゲームの詳細分析**:
   - 平均Budget残高
   - 平均ターン数
   - どの陣営/AIが多いか

2. **ドロー/サーチカードの使用頻度**:
   - Strategy cardsの使用回数
   - リポジトリからのデプロイ回数

3. **Budget温存の影響**:
   - Budgetを使わずにゲームが長引く → リポジトリ切れ

#### 対策案

- **AIのBudget使用を促進**: deployFloorを下げる
- **リポジトリサイズの調整**: 30枚 → 32-35枚に増加を検討
- **ドロー制限**: 過剰なドロー/サーチを制限

### 4. GuruguruAI/MiracleAIの改善（低優先度）

#### 現状
- GuruguruAI: 42%
- MiracleAI: 44%

#### 提案
- パラメータチューニング
